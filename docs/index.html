How the pieces fit

A small job on the Mac mirrors an Apple Photos album to the Pi; the Pi runs the display and a web UI.

Mac (Apple Photos album) │ sync_album.py — crop/resize to 64×64 PNG, rsync --delete ▼ Raspberry Pi /home/pi/spotipi-photos/photos/ ← exact mirror of the album │ displaySpotipi.py — slideshow + Spotify priority, reads state.json live │ client/app.py — web UI on :80, writes state.json ▼ 64×64 RGB LED matrix

Why the screen-off timer finally works: the original web app turned the panel on/off by systemctl start/stop-ing the display service and restarted it on every brightness change — fragile timers and brightness. Here the display daemon is always running and re-reads config/state.json every loop. The web UI only writes that file — no service juggling — so brightness is live and the timer is enforced reliably by the daemon itself.

Control panel

A web UI on the Pi (port 80) — open it from any browser or phone on your network.

Modes

On (auto) shows Spotify art while music plays and the photo slideshow otherwise; or force Photos only / Spotify only, or Off (daemon keeps running).

Live brightness

A 1–100 slider that takes effect instantly, no restart.

Photo slideshow

Set seconds per photo, plus a Change photo button to skip to the next one. Photos play in a shuffled order — every photo once per pass, never repeating back-to-back.

Screen timer

Turn the panel off after N minutes; the countdown restarts when you save it or tap a display button.

Daily schedule

A recurring off-window that correctly handles overnight, e.g. 23:00 → 07:00.

Sunrise/sunset dimmer

Automatically drops to a lower night brightness between sunset and sunrise — times computed from your latitude/longitude, no internet or API key needed.

"Now on the panel" dashboard

A live snapshot at the top of the web UI — what's actually on the matrix right now, refreshed every few seconds.

Uptime

The daemon publishes a small status.json plus a 64×64 current.png snapshot each time the panel changes, with a 10-second heartbeat. The web app reads those and adds Pi temp/uptime/last-sync locally — so the dashboard needs no extra Spotify credentials. These runtime files are regenerated by the daemon and aren't shipped in the release.

Set up

Two halves: the Raspberry Pi (display + web UI) and the Mac (Apple Photos → Pi sync).

On the Pi — copy the spotipi-photos/ folder over, make sure the Spotify token exists, then:

cd ~/spotipi-photos
sudo bash install_pi.sh      # installs deps, asks for your Spotify creds,
                             # creates the spotipi + spotipi-client services

Open http://<pi-ip>. Set your real panel details (rows/columns, hardware_mapping, gpio_slowdown) in config/rgb_options.ini.

On the Mac — create an Apple Photos album named exactly Spotipi, then:

cd spotipi-photos/mac
bash install_mac.sh
python3 sync_album.py --dry-run   # preview
python3 sync_album.py             # sync (rsync --delete keeps the Pi mirrored)

Remove a photo from the album and it disappears from the Pi automatically. A LaunchAgent can run the sync every few minutes, and an optional auto-updater pushes new code to the Pi and rolls back if a service fails to start.

Spotify credentials and the token are entered at install time and live only on the Pi (never in the repo). Needs scope user-read-currently-playing user-read-playback-state; re-run the token generation roughly every 6 months if album art stops appearing.
